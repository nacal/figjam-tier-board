# FigJam Tier表

FigJam 上で Tier 表（tiermaker.com のようなランキング表）を作るためのプラグイン。

ランキングの対象は **FigJam の素の付箋**。このプラグインが担当するのは「行（ティア）の枠を用意して管理すること」だけで、付箋の生成・整列・集計は行わない。

## できること

| 機能 | 内容 |
| --- | --- |
| 盤面作成 | S / A / B / C / D の 5 行を生成 |
| 行の追加 | 末尾に新しい行を追加 |
| 行の削除 | 行を削除。中の付箋は消さずキャンバスに残す |
| リネーム | 行の名前を変更 |
| 色変更 | 行の背景色をプリセットから選択 |
| 並び替え | 行の順序を入れ替え（パネルの ⠿ をドラッグ&ドロップ、または ↑↓） |
| 左寄せ整列 | 行の中の付箋を左上から詰めて並べる。ドラッグして落とした位置で順位が決まる |
| 幅の変更 | どれか1行の右端を引っ張ると、盤面全体の幅が変わる |

## 設計

- 行は `SectionNode`。セクションは幾何的に内包したノードを自動的に子にするため、付箋の所属判定が `parent` を見るだけで済む。プラグインが作った付箋か手作りの付箋かも区別しない
- ティア行かどうかは、セクションの plugin data（`figjamTierRow`）で判別する。無関係なセクションは対象外
- **行の順序はキャンバス上の y 座標を唯一の正とする。** 順序を別途保存しない。パネルを開くたびにページ上のティア行を y の昇順で読んで一覧を組み立てるため、FigJam 上で手でセクションをドラッグして動かしても、次に開いた時点でその並びがそのまま反映される
- 並び替えは、配列上で順序を入れ替えたあと全行の y を上から詰め直す。詰め直しの基準は**今いちばん上にある行の左上**であって、新しい順序の先頭に来た行が今いる場所ではない。後者を基準にすると、並べ替えのたびに盤面ごとその行の位置へ飛ぶ。全行の最小 x を取るのも不可で、1 行だけ横にずらしたときに盤面全体が引っ張られる
- 行を削除するときは、セクションを消す前に中の子ノードを絶対座標を保ったまま親（ページ）へ退避させる。先にセクションを消すと子ごと消える
- 行を削除したときは、中身を盤面の下へ逃がしてから隙間を詰める。元の場所に残すと、詰め直した行がそれを踏んで自動的に子にしてしまい、意図しないティアへ移る
- 行同士は隙間なく積む。各行の左端には、ティア名を表示する色付きのセル（`ShapeWithText`）を子として置く。これはランキング対象ではないので plugin data（`figjamTierLabel`）で見分けて整列から除外し、`locked = true` でキャンバス上から掴めないようにしている
- 既定幅は 240px の付箋がちょうど 10 枚入る 2964px（`色セル 300 + 余白 24*2 + 240*10 + 間隔 24*9`）
- 盤面の幅は、各行に「前回書き込んだ幅」を plugin data で持たせ、実際の幅と食い違う行を探して見つける。ユーザーが1行の右端を引っ張ると、その幅が全行に伝播する
- 幅を縮めるときは、先に新しい幅で付箋を配置し直してからセクションを縮める。順序が逆だと、はみ出した付箋が行から抜け落ちる
- 行の見た目（暗い面と境界線）は整列のたびに当て直す。色セルが無かった頃に作った盤面も、次の整列で新しい見た目へ自動的に移行する
- **行の中の順位は付箋の中心 x を唯一の正とする。** 整列は中心 x の昇順に読んで左上から詰め直すだけなので、「ドラッグして落とした位置で順位が決まり、落とした先の付箋と場所が入れ替わる」が自然に出る。順位を別途保存しない点は行の順序と同じ
- 横幅に収まらない付箋は折り返し、行の高さを伸ばす。伸ばすときは配置の前、縮めるときは配置の後にリサイズする。先に縮めるとセクションの外に出た付箋が行から抜けてしまう
- 自動整列は `figma.currentPage.on('nodechange')` で拾う。ドラッグ中に割り込むと掴んでいる付箋が飛ぶので 320ms デバウンスし、整列自身が起こす変更は 400ms の抑制窓で無視する。`origin` が `REMOTE`（他の参加者の操作）には反応しない — 全員が同じ行を奪い合って動かし続けるため
- 既定幅 1608px は 240px の付箋がちょうど 6 枚入る値
- 盤面はページ上の既存コンテンツの下に作る。ビューポート中央に作ると既存の付箋の上に行が重なり、セクションがそれを丸ごと子にしてしまうため。ページが空のときだけビューポート中央に置く

### 既知の制約（v1 では対応しない）

- 複数人が同時に同じ行を操作すると競合しうる
- プラグインの UI と実行中であることは実行者本人にしか見えない（生成・変更されたセクションは全員に見える）
- 行内の順位は x 座標の昇順（左が上位）とみなすが、v1 に読み取り機能はないので、これは将来の集計機能を足す場合の前提として残しているだけ
- 1 ページにつき盤面はひとつ。順序をページ全体の y で決めるため、2 つ目の盤面を作ると混ざる

## 開発

```sh
npm install
npm run build   # src/code.ts -> dist/code.js
npm run watch   # 変更を監視してビルド
npm test        # ビルドしてロジックのテストを実行
```

テストは `test/harness.mjs` で Figma Plugin API を最小限モックし、コンパイル済みの `dist/code.js` を `vm` で読み込んで UI からのメッセージで駆動する。セクションが重なったノードを自動的に子にする挙動も近似してあるので、付箋の所属判定・左寄せ整列・行削除時の退避を Figma なしで確かめられる。

Figma デスクトップアプリで **Plugins → Development → Import plugin from manifest…** から `manifest.json` を選ぶ。外部通信は行わない（`networkAccess.allowedDomains: ["none"]`）。

## 構成

```
manifest.json        プラグイン定義（editorType: figjam）
ui.html              パネル UI（バニラ JS）
src/code.ts          メインスレッド。セクションの生成・配置・整列・削除
test/harness.mjs     Figma Plugin API のモック
test/arrange.test.mjs
```
